## Findings and limits

- Dashboard calls the shared client: production `/nexus/api/dashboard/project-usage/`; Django receives `/api/dashboard/project-usage/` through the existing proxy. A per-project "data is currently unavailable" message is generated by `ProjectUsageSummaryView` when that project's source raises `ProjectUnavailable`. The summary can return HTTP 200 with one or both entries unavailable; the per-count list uses HTTP 503 for a source failure. Check the JSON as well as HTTP status.
- `usage.py` reads external GSTR `Gstr_db.dbo.*` and Barcode `PRNPRINT.dbo.Customers`, `Licenses`, `LicenseActivations`, then merges active Nexus registrations. Configured DB names may differ in production.
- The supplied historical `Invalid object name 'PRNPRINT.dbo.Customers'` identifies a failing three-part reference at that time. It does not establish whether the current cause is a missing database/table, a different schema/case, the wrong SQL instance, permissions, or deployment/configuration drift. It cannot explain GSTR on its own.
- LOCAL read-only SQL checks show both configured databases accessible, every expected table visible in dbo, SELECT permitted, and both actual summary queries successful. These results do not establish production object validity.
- Nexus Customer List uses ProjectCustomer records; runtime usage has a different base set. Local GSTR has one runtime usage unit and zero Nexus customers; Barcode has six usage units but five active Nexus registrations. Automatically replacing runtime usage with Nexus-only data would omit real units. No silent fallback was added. A change in the authoritative source requires production evidence and an explicit business decision.
- Preserved rules: active GSTR licensed devices, completed import events, unmatched active Nexus registrations; Barcode non-revoked legacy licenses merged by serial with active Nexus registrations, activation/validation/device usage; current active-device uniqueness prevents duplicating Nexus customers. Inactive/cancelled Nexus registrations remain excluded by the existing active-unit rules. Expire uses active-status Nexus Trial/1-Year records with effective expiry <= now; Lifetime and unstarted device trials are excluded. No expiry policy was changed.
- UI had four count cards and four inner columns; it now has Used (existing green), Not Used (red), Expire (blue), three columns, and two project panels on wider screens. Count links retain project/status and expired-only filtering. Report permissions still control drilldowns.
- Two additional failures were outside `_run`'s error handling: invalid datasource names and Nexus ORM expiry-query failures. Public summary/list/report functions now translate those database/configuration exceptions into ProjectUnavailable, preserving the original exception chain for existing server logging. Other projects still load; no zero counts replace failures.
- A failed dashboard refresh previously hid the new error behind old counts; it now shows the API error.

### GSTR minimum read-only access proposal -- DBA review/approval only, NOT EXECUTED

The current successful-import usage definition requires Gstr_db. Nexus registrations do not contain the missing runtime completed-import history; replacing it would change the business definition. The app login needs a database user mapped to the existing server login in the actual GSTR database, CONNECT to that database, and SELECT on just the columns referenced by the current query. No INSERT/UPDATE/DELETE, db_owner, db_datareader, TRUSTWORTHY or cross-database ownership-chaining changes are required.

First the DBA should inspect the existing user SID/mapping and explicit DENY entries. Do not run CREATE USER if an existing user is already mapped under another name; an orphaned user may need an approved mapping correction instead. The following is a proposal using the confirmed error's names, not an executed script. Run only after the DBA confirms actual schema/object names and approval for the database privilege change:

```sql
USE [Gstr_db];
-- Only if the DBA confirms no database user maps to this existing login:
-- CREATE USER [nexus_app] FOR LOGIN [nexus_app];
-- If an existing database user has a broken mapping, the DBA must review it first:
-- ALTER USER [nexus_app] WITH LOGIN = [nexus_app];
GRANT CONNECT TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[licensed_device_tbl]
    ([id], [license_id], [device_fingerprint], [device_name], [status]) TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[product_license_tbl]
    ([id], [customer_id], [licensed_gstin], [licensed_tally_serial]) TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[auth_user]
    ([id], [username]) TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[superadmin_customerprofile]
    ([id], [user_id], [business_name]) TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[companydetails_tbl]
    ([id], [gstin], [company_name]) TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[local_tally_agent_tbl]
    ([id], [device_id]) TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[gst_import_batch_tbl]
    ([id], [product_license_id]) TO [nexus_app];
GRANT SELECT ON OBJECT::[dbo].[tally_import_job_tbl]
    ([local_agent_id], [batch_id], [completed_at], [started_at], [status]) TO [nexus_app];
```

Do not grant `auth_user.password` access. Existing Nexus database access is separately needed for registrations/device/expiry queries and is already used by the working Customer List. The diagnostic's object-level `HAS_PERMS_BY_NAME(..., 'SELECT')` can be false for column-only grants; successful real summary/list/report queries are the definitive verification. Do not grant broader rights just to make a metadata flag true.

SQL syntax/reference: [Microsoft GRANT object permissions](https://learn.microsoft.com/en-us/sql/t-sql/statements/grant-object-permissions-transact-sql) and [Microsoft error 916](https://learn.microsoft.com/en-us/sql/relational-databases/errors-events/mssqlserver-916-database-engine-error).
