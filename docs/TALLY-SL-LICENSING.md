# Nexus Central Licensing API — Tally SL products (v1)

Status legend used in this document: **LOCAL** = implemented and verified in the isolated local test environment; **LIVE** = verified on `https://saitallyexpert.in/nexus/`.
**At the time of writing, the Tally SL `v1` API is LOCAL only. It is not deployed.** (See "Live server verification".)

Every request/response below was captured from the automated end-to-end test `apps/tallysl/test_integration_flow.py`
(real HTTP calls through Django, isolated test database). Tokens are shortened to `<token>`.

## 1. Concepts
| Term | Meaning |
|---|---|
| Product | a row in `tallysl_tallyproduct` (code `gstr2tally`); future Python/.NET/web/EXE/APK products are added by backend administration |
| Tally Serial Number = Product Serial Number = **User ID** | read from TallyPrime by the GSTR client; never generated by Nexus |
| **Nexus Activation Key** | generated by Nexus when a Superadmin assigns a plan; separate from any Tally credential; stored only as a hash |
| **License Plan** | `TRIAL`, `ANNUAL` (1 year), `LIFETIME`. Separate fields: `trial_days`, `activated_at`, `expires_at`, status, authorised device |
| Product key (`X-Product-Key`) | identifies the **product**. It is *not* what authorises a customer (see §6) |
| Session token (`Authorization: Bearer`) | issued by login / activation; revocable server-side |

Rules enforced by Nexus: registration alone grants no licence (plan starts `pending`); expiry is computed on the server; one product-serial per product; a product key only works for its own product; one enrolled device per licence.

## 2. Base URL and environments
| | Base URL |
|---|---|
| Development | your local Nexus, e.g. `http://127.0.0.1:8001/api/v1/tally-sl/gstr2tally/` |
| Production | `https://saitallyexpert.in/nexus/api/v1/tally-sl/gstr2tally/` (HTTPS only; Django redirects/HSTS when `DEBUG` is off) |

Make the base URL configuration (`NEXUS_BASE_URL`), never a literal in source. Never ship a LAN IP.

### Live server verification (read-only, unauthenticated GET, performed when this document was written)
| URL | Result | Meaning |
|---|---|---|
| `GET https://saitallyexpert.in/nexus/api/health/` | 200 `{"status":"ok","database":"ok"}` | **LIVE** server and database reachable |
| `GET …/nexus/api/portal/prn-auto-print/login/` | 401 `Invalid or missing project key` | **LIVE** PRN portal route exists, behaves as before |
| `GET …/nexus/api/v1/tally-sl/gstr2tally/identify/` | **404** | Tally SL v1 API is **NOT deployed** on the live server |

Nothing in this repository has been deployed, migrated or configured on production.

## 3. Common conventions
* JSON bodies, `Content-Type: application/json`, UTF-8; timestamps ISO-8601 UTC.
* Errors always `{"message": "...", "code": "stable_code", "errors": {"field": ["..."]}}`.
  Statuses: 400 validation/invalid code, 401 bad credentials / invalid or revoked token (`session_revoked`), 403 forbidden or licence not authorised, 404, 409 conflict (`account_exists`, `confirmation_required`), 429 locked/throttled.
* Rate limit per client IP (`TALLY_THROTTLE_RATE`, default 120/min), account lockout, code attempt limits.
* Every security-relevant step is written to the Nexus audit log with IP.

## 4. Client API reference
All paths are relative to the base URL in §2. `<token>` = `Authorization: Bearer <token>`.

### 2. Customer registration (Sign Up)

`POST /register/`

**Auth:** `X-Product-Key` only

| Field | Required | Notes |
|---|---|---|
| `name` | yes | ≤100 chars |
| `email` | yes | valid email |
| `contact_number` | yes | 9–19 digits, optional leading +, spaces/dashes allowed |
| `tally_serial` | yes | 5–30 letters/digits. Must be the serial read from TallyPrime by the client — never typed or generated. Becomes the User ID |
| `product` | no | if sent it must equal the product in the URL |

Creates the customer and a **Pending** licence (no access). A temporary password is emailed (never returned in the response); Superadmins are notified; the customer appears in *GSTR2Tally › Customers* at once.

Request
```json
{
  "name": "Ravi Kumar",
  "email": "ravi@example.com",
  "contact_number": "9876543210",
  "tally_serial": "700456789",
  "product": "gstr2tally"
}
```

Response — HTTP 201
```json
{
  "user_id": "700456789",
  "status": "registered",
  "license_status": "pending",
  "message": "Registered. A temporary password has been emailed. Your license will be activated by Sai Infosys.",
  "welcome_email": "submitted"
}
```

Error — HTTP 409 (`account_exists`)
```json
{
  "message": "An account already exists for this Tally Serial Number.",
  "code": "account_exists",
  "errors": {}
}
```

Error — HTTP 400 (`validation_error`)
```json
{
  "message": "Please correct the highlighted fields.",
  "errors": {
    "email": [
      "Enter a valid email address."
    ]
  },
  "code": "validation_error"
}
```

## 5. Flow for the GSTR (.NET + TallyPrime) application
1. Read the **Tally Serial Number** from TallyPrime through your supported integration. Show it read-only.
2. **Sign Up** → `register/`. Tell the user a temporary password was emailed and that Sai Infosys activates the licence.
3. Superadmin opens *GSTR2Tally › Customers › customer* and assigns **License Plan** (Trial days / Annual / Lifetime) → Nexus emails the **Activation Key**.
4. **Activate User** on each computer: `activate/request-code/` → user enters the emailed code + Activation Key → `activate/verify/` → if `requires_confirmation`, show `message` and ask → `activate/confirm/` (`confirm_transfer: true` only after the user agrees). Store the returned `token`.
5. **Sign In** (`auth/login/`, with the `device` block). First login with a temporary password: call `auth/change-password/`.
6. After sign-in: `tally-info/` with the verified Tally details, then `license/status/` (gate the app on `authorized`), then `usage/open/`.
7. While running: poll `session/` (or call `license/status/`) every few minutes; on 401 `session_revoked` sign the user out and explain the licence moved to another device. Refresh with `auth/refresh/` before the token expires.
8. Offline: you may keep running until `lease_until`; the next online check enforces revocation/expiry. **A machine that is switched off or offline cannot be told instantly** — shorten `TALLY_LEASE_DAYS` (default 7) to tighten this.

## 6. Authentication model by client type (do not put server secrets in distributed apps)
The product key is only a **product identifier + routing/rate-limit handle**. Everything sensitive is protected by customer credentials (password, emailed single-use code, Activation Key), server-side device binding and revocable tokens. Treat it as public for client apps:

| Client | Where the product key lives | Notes |
|---|---|---|
| **Server-side (Django, ASP.NET, Node, your own backend)** | environment variable / secret store | may call Nexus on behalf of users; keep out of source control and logs |
| **Windows EXE / .NET desktop (GSTR)** | embedded as a *public product identifier* (obfuscation is not security) | rely on customer login + device block; store the session token with DPAPI (`ProtectedData`), never the password; rotate the key via a new release if it is abused (ask Nexus admin to deactivate it) |
| **Android APK** | `BuildConfig` constant (public identifier) | store token in EncryptedSharedPreferences/Keystore; use a per-install `client_device_id` (random UUID) and `fingerprint` that is not a hardware serial you cannot change; Play Integrity attestation is **not implemented** by Nexus |
| **Browser JavaScript** | **do not** call Nexus directly with the key from the browser; call your own backend, which holds the key and relays | avoids exposing the key and CORS issues |

Short-lived tokens: set `TALLY_SESSION_MAX_AGE` (e.g. 3600) and use `auth/refresh/`. Device verification: `client_device_id` + `fingerprint` are bound to the licence at activation; another machine cannot reuse the token (`device_not_authorized`).

## 7. .NET (C#) examples — real contracts
```csharp
using System.Net.Http.Json;
using System.Net.Http.Headers;
using System.Text.Json;

public sealed class NexusClient
{
    private readonly HttpClient _http;
    public NexusClient(string baseUrl, string productKey)          // baseUrl from configuration, e.g. https://saitallyexpert.in/nexus/
    {
        _http = new HttpClient { BaseAddress = new Uri(baseUrl.TrimEnd('/') + "/api/v1/tally-sl/gstr2tally/") };
        _http.DefaultRequestHeaders.Add("X-Product-Key", productKey);
        _http.Timeout = TimeSpan.FromSeconds(20);
    }

    public sealed record Device(string client_device_id, string fingerprint, string device_name, string app_version);

    private static async Task<JsonElement> Read(HttpResponseMessage r)
    {
        var body = await r.Content.ReadFromJsonAsync<JsonElement>();
        if (!r.IsSuccessStatusCode)                                   // {"message","code","errors"}
            throw new NexusException((int)r.StatusCode, body.GetProperty("code").GetString()!, body.GetProperty("message").GetString()!);
        return body;
    }

    // Sign Up: tallySerial MUST come from the verified TallyPrime integration
    public async Task<JsonElement> RegisterAsync(string name, string email, string phone, string tallySerial) =>
        await Read(await _http.PostAsJsonAsync("register/", new { name, email, contact_number = phone, tally_serial = tallySerial, product = "gstr2tally" }));

    public async Task<string> LoginAsync(string userId, string password, Device device)
    {
        var body = await Read(await _http.PostAsJsonAsync("auth/login/", new { user_id = userId, password, device }));
        if (body.GetProperty("must_change_password").GetBoolean()) { /* prompt for a new password, then ChangePasswordAsync */ }
        return body.GetProperty("token").GetString()!;               // keep in DPAPI-protected storage
    }

    private HttpRequestMessage Authed(HttpMethod m, string path, string token, object? json = null)
    {
        var req = new HttpRequestMessage(m, path);
        req.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token);
        if (json != null) req.Content = JsonContent.Create(json);
        return req;
    }

    public async Task ChangePasswordAsync(string token, string current, string next) =>
        await Read(await _http.SendAsync(Authed(HttpMethod.Post, "auth/change-password/", token, new { current_password = current, new_password = next })));

    // Verified TallyPrime details only; list exactly the fields TallyPrime integration verified
    public async Task<JsonElement> SyncTallyAsync(string token, string edition, string tss, int? virtualUsers, string admin,
                                                  string gateway, string tallyEmail, DateOnly? tssExpiry) =>
        await Read(await _http.SendAsync(Authed(HttpMethod.Post, "tally-info/", token, new
        {
            edition, tss_details = tss, virtual_user_limit = virtualUsers, license_administrator = admin, gateway_server = gateway,
            registered_email = tallyEmail, tss_expiry_date = tssExpiry?.ToString("yyyy-MM-dd"),
            verified_fields = new[] { "edition", "tss_details", "virtual_user_limit", "license_administrator", "gateway_server", "registered_email", "tss_expiry_date" }
        })));

    public async Task<JsonElement> LicenseStatusAsync(string token) =>
        await Read(await _http.SendAsync(Authed(HttpMethod.Get, "license/status/", token)));   // gate on ["authorized"]; show ["state"]; offline until ["lease_until"]

    public async Task<JsonElement> ReportOpenAsync(string token, string appVersion) =>
        await Read(await _http.SendAsync(Authed(HttpMethod.Post, "usage/open/", token, new { app_version = appVersion })));

    public async Task<string> RefreshAsync(string token) =>
        (await Read(await _http.SendAsync(Authed(HttpMethod.Post, "auth/refresh/", token)))).GetProperty("token").GetString()!;

    // Activate User (new / replacement laptop)
    public Task RequestCodeAsync(string userId) => _http.PostAsJsonAsync("activate/request-code/", new { user_id = userId });
    public async Task<JsonElement> VerifyAsync(string userId, string code, string activationKey) =>
        await Read(await _http.PostAsJsonAsync("activate/verify/", new { user_id = userId, code, activation_key = activationKey }));
    public async Task<JsonElement> ConfirmAsync(string ticket, Device device, bool confirmTransfer) =>
        await Read(await _http.PostAsJsonAsync("activate/confirm/", new { ticket, device, confirm_transfer = confirmTransfer }));
}

public sealed class NexusException : Exception
{
    public int Status { get; } public string Code { get; }
    public NexusException(int status, string code, string message) : base(message) { Status = status; Code = code; }
}
```
Typical start-up:
```csharp
var nexus = new NexusClient(config["NexusBaseUrl"], config["NexusProductKey"]);
var device = new NexusClient.Device(installId, MachineFingerprint(), Environment.MachineName, "1.0.0");
```

Django web apps: keep the key in `settings` loaded from the environment, call Nexus from views/services, never from templates/JS. Non-Tally products use their own product code and identity: register them with `tally_serial` holding that product's customer/serial identifier.

## 9. Web, Windows EXE, Android — checklist
* **Web:** browser → your backend → Nexus. The backend stores the session token per user (server session), refreshes it, and checks `license/status/` per request/session.
* **Windows EXE:** HTTPS only (reject invalid certificates); token in DPAPI; `client_device_id` generated once and stored per-user; `fingerprint` = stable hardware/OS identifier; handle offline with `lease_until`.
* **Android APK:** HTTPS only (no cleartext), certificate pinning optional; token in Keystore-backed storage; random `client_device_id`; keep `fingerprint` stable across app restarts; no server secrets in the APK.

## 10. Onboarding a new product (trusted backend administration only)
There is no public or UI endpoint to create products or keys.
1. A developer adds the product row (Django admin shell / data migration under change control).
2. `python manage.py create_tally_product_key <code>` prints a key once; only its hash is stored.
3. The product's own backend (or build pipeline) receives the key as a secret; client apps follow §6.
Seeded today: `gstr2tally`.

Usage classification order: **New** (registered ≤7 d) → **One-Time** (exactly 1 opening) → **Speed** (≥15 distinct IST days in last 30) → **Normal** (returning, ≥1 active day in window). Internal buckets not shown as categories: `zero_use`, `dormant`.

## 12. Database migrations & safety
`tallysl.0001_initial` creates only `tallysl_*` tables/indexes/constraints (foreign keys to `auth_user` only); `0002_seed_gstr2tally` inserts one product row. No ALTER/DROP of any existing table (verified with `sqlmigrate`). PRN tables, APIs, keys and flows are not touched.

## 13. Production deployment requirements (not yet performed)
1. Back up the Nexus SQL Server database. 2. Deploy backend + `npm run build` frontend. 3. `python manage.py migrate` — review `showmigrations` first: pending migrations of *other* apps (e.g. `registrations`) would be applied too. 4. `create_tally_product_key gstr2tally` and hand the key to the GSTR team through a secure channel. 5. Smoke test on production: `GET /nexus/api/health/`, `identify/` with the key, then one real registration by the GSTR team. 8. Keep the old release available.
**Rollback:** redeploy the previous code (the new tables are inert without it). Full revert: `python manage.py migrate tallysl zero` (drops only `tallysl_*`), remove `apps.tallysl` from `INSTALLED_APPS` and its line from `config/urls.py`.

## 14. Known limitations
Offline revocation is enforced at the next online check (`lease_until`); no push channel; no mobile attestation; Tally data is only what the client reports; customers' Tally ports are never contacted by Nexus.
