UNIVERSE customer flow

1
External app → Nexus

Register

POST customers/register returns HTTP 202 PENDING_REVIEW. Nothing is issued yet.

2
Superadmin / Admin

Review in the approval popup

  • 9-digit Serial / User ID, starts with 9, editable, regenerate icon
  • Temporary password: 3+ characters; show, copy and regenerate icons
  • License: Trial, Yearly, Lifetime or Custom, set in one row
  • Device Activation: AUTOMATIC
3
Nexus

Save & Allow

Creates the customer and license, then sends one welcome email with the User ID, temporary password, license type, expiry and login URL. Hold and Reject are also available.

4
Customer app → Nexus

Authorise the device

POST devices/authorize returns AUTHORIZED and a session. A second device gets 409 TRANSFER_CONFIRMATION_REQUIRED and must send confirm_transfer. sessions/introspect checks the session.

The temporary password must be changed at first login; rate limiting and lockout stay on. The activation key is internal, stored only as a hash, never shown or emailed.

Customer Management card

After approval a customer opens in one card with four tabs: Customer, License, Usage & Devices and History.

  • License tab: extend trial, renew, suspend or reactivate, change license type.
  • Bottom right: Edit Customer (opens the customer form, never Edit Project) and Delete Customer (asks first, then deletes permanently).
  • Delete a test customer and register again: it returns as Pending Review.

API Integration for developers

Setup wizard

Protocol, framework and authentication (Custom, Basic, OAuth2), then push (webhook) or poll, detect fields, and validate.

Credentials

Client ID plus a hashed API secret. The secret is shown once; rotation cancels the old one.

Developer email

Short: project, API base, Client ID, a register example and one link (24 hours, single use) that issues a new API secret.

Sync Logs

Received, rejected, unauthenticated and handoff-redeemed events. No secret, token or password is ever logged.

Before production

  1. Take a full SQL Server backup and test-restore it into a scratch database.
  2. Deploy backend and frontend together, then run migrate (applies 0008). Rollback: migrate integrations 0007 plus the backup.
  3. Set NEXUS_PUBLIC_API_BASE, NEXUS_PUBLIC_APP_URL and working SMTP.
  4. Check the public routes answer 401/405, not 404. devices/authorize returns 404 on production today.
  5. Give every Admin per-user permission grants.
  6. Smoke test with a test project: register, approve, email, device authorisation, delete.
  7. Create MMM001 again on production and give Mothys those new credentials.
  8. Regression check on legacy MOTHYS, GSTR2Tally and Barcode AutoPrint.
